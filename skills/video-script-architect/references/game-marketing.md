# 游戏发行视频素材流程

适用于塔防游戏及其他项目的国内外平台投放、Playable 互动广告、社媒活动、KOL 合作和直播。目标是建立可复用的项目事实基线，再针对具体渠道和本次目标产出可制作、可测试、可迭代的创意。

## 1. 按项目建立资料卡

每个项目独立整理信息。先查用户已给的文档、图片、录屏、过往讨论和工作区文件，再补问影响当前任务的缺口。资料卡记录来源、版本或日期，并区分“已确认”“待确认”“创意假设”；用户修正后更新对应项目，避免不同游戏的设定串用。用户只要一次性方向探索时，可以用会话内资料卡；需要长期复用且有可写工作区时，可建立项目独立的 Markdown 文件，文件名清楚标明项目，写入前先确认不覆盖现有资料。

建议字段：

| 类别 | 需要采集的内容 |
| --- | --- |
| 产品 | 游戏名称与版本、品类和玩法循环、塔防机制与差异点、角色/敌人/关卡、美术与世界观、真实可展示的游戏画面 |
| 用户与市场 | 目标人群、核心动机和阻碍、投放国家/地区及语言、平台、竞品和可参考的相似游戏 |
| 卖点与边界 | 卖点优先级和证据、品牌调性、禁用表达、不可误导的玩法与福利、审核或法务约束 |
| 增长目标 | 获客/召回/预注册/活动参与等目标、转化路径、素材规格、预算或制作资源、成效指标与已有测试数据 |
| 本次需求 | 素材用途、活动主题/规则/时间、主推内容、目标渠道、交付件数、上线节奏、现有素材和反馈 |

首次接到新项目时，优先索取游戏核心资料、真实玩法画面或描述、主要卖点、目标市场与渠道、品牌限制。活动素材缺少活动规则、时间、奖励或参与方式时应询问，避免自行编造。已有足够资料就直接工作，不反复索要完整表格。

## 2. 研究与对标

围绕本次项目、目标受众、渠道和卖点查找真实案例，竞品及玩法/情绪/表达方式相近的非竞品都可参考。优先用官方广告库、游戏官方账号、平台创意中心、可核查的投放案例和公开分析；标注平台、地区、日期和可验证的表现证据。对每个参考提炼“可借鉴的创意机制”和“不能照搬的具体内容”，再判断与本项目调性、卖点、制作条件是否匹配。

把高传播和高转化逻辑当作待验证假设：首秒停留、冲突与目标是否易懂、玩法证据是否足够、爽点/失败点/反转是否有递进、品牌与落地页承诺是否一致、结尾行动是否清楚。没有实际投放数据时，以“预期优势/风险/建议测试”表达，不伪造 CPI、CTR、完播率或 ROAS。

## 3. 根据用途选择创意方法

| 用途 | 重点 | 典型交付 |
| --- | --- | --- |
| 信息流广告 | 移动端快速看懂的开场钩子、单条素材的核心卖点与真实玩法证明、短节奏、清晰行动、便于批量变体和测试 | 创意方向卡、首秒钩子、脚本/分镜、关键画面、文案和版本矩阵 |
| Playable 互动广告 | 在受限时长和技术规格内，让玩家通过真实可执行的操作体验卖点；按时间段与交互状态设计输入、反馈、分支和结束 | 时间轴、状态/分支表、玩家操作、系统反馈、CTA 与技术验收清单；详细规则见 [playable.md](playable.md) |
| 社媒视频 | 平台语境、账号人设、话题讨论和互动价值；围绕活动调性与社群关系组织内容，避免直接把买量广告改尺寸重发 | 栏目/内容系列、平台版本、发布节奏、互动话题、活动脚本 |
| KOL 合作 | 创作者受众与表达习惯、体验真实性、可讲的游戏卖点、明确的必说点和自由发挥空间 | 创作者筛选维度、KOL brief、内容切入点、可选桥段、口播要点与限制 |
| 直播 | 即时演示、关卡挑战与观众参与、主持节奏、活动节点与转化链路 | 直播主题、流程表、演示关卡、互动机制、口播卡与应急内容 |

国际市场需按地区核对语言、文化语境、平台习惯、游戏术语、活动时间和当地合规要求；不要把中文梗直译。具体平台格式、广告政策和工具能力会变化，制作前查当前官方规格。

## 4. 创意方向和交付标准

在用户要求探索时，给出彼此有辨识度的方向，而不是同一个脚本换三句开头。每条方向尽量包括：目标人群与使用场景、核心洞察、关联卖点、可视化钩子、展开机制、真实玩法或素材证据、情绪收益、适合渠道、制作难度与限制、最小可测试版本。清楚指出创意依据和不确定之处。

用户要求脚本时，再展开镜头/画面、动作、字幕/台词/音效、时长估算、转场与 CTA，并核对游戏机制、风格及制作条件。若视频将由 AI 工具生成，按具体工具的现行能力核对时长、参考图、跨镜一致性及提示词格式；不要默认使用短片流程里所有角色设定和长篇分镜步骤。

社媒活动需先读活动 brief；没有 brief 时索取活动目标、规则、日期、主推奖励或内容、平台和禁用项。活动细节不完整但用户希望先看方向时，可给概念草案并显著标记待确认项。

## 5. 快速迭代与提前准备

把每个方向拆成可控变量，如开场钩子、卖点角度、玩法场景、叙事视角、素材形式、口播、字幕、结尾行动。优先设计少量能检验明确假设的版本，说明每个版本要验证什么；避免一次同时改动过多变量而无法归因。

交付时根据可用数据提出预判：可能疲劳的元素、可提前储备的关卡/角色/活动画面、可替换的钩子和结尾、跨地区本地化版本、节日及版本节点。出现真实投放或社媒表现后，用实际指标、评论和观看流失点复盘，再更新项目资料卡中的“已验证结论”；把推断保留为假设。

## 6. 协作节奏

先确认本次要的是方向、脚本、批量变体还是复盘；缺少关键事实时集中提问。若用户给出明确 brief，就直接按 brief 交付。创意方向阶段可以请用户选方向继续深化，但不强制每个阶段停下来确认；按照上线时效和用户指令调整深度。对多项目请求，逐项目维护事实和结论，不交叉引用未经确认的卖点。
