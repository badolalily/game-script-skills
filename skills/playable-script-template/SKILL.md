# Playable脚本模板

当用户要求编写、整理、优化或改写手机游戏 Playable 创意脚本、可互动广告、演示视频分镜或制作对接稿时，默认使用本技能。目标是把用户提供的玩法、角色、素材限制和操作流程整理成制作方、开发方、AI 视频团队都能执行的交付稿，而不是只输出线性视频描述。

若用户只要求模板，输出可复用模板；若用户给出具体 brief，直接替换模板字段生成完整脚本。缺失信息用“待确认”或“广告简化假设”标注，不擅自编造成真实游戏机制。

可参考 [references/output-example.md](references/output-example.md) 了解最小输出结构。

## 固定输出结构

除非用户明确要求其它格式，按以下九部分输出，顺序不要调整。

### 一、项目基础信息

用两列表格输出，表头固定为“项目 / 内容”。至少包含：

- 项目
- 素材类型
- 视频比例
- 总时长
- 美术风格
- 核心体验
- 正确选择或正确操作
- 主要卖点
- 制作依据
- 时间口径

“时间口径”必须说明：时间码用于制作演示视频；真实 Playable 在点击、拖拽或选择处等待玩家输入；无操作提示只引导，不替玩家完成最终选择或关键拖拽。

### 二、核心制作规则

使用编号条目写清不可漂移的规则，优先覆盖：

- 角色、道具、载具、敌人和 UI 的外观锁定。
- 角色与技能、颜色、图标、攻击效果的唯一对应关系。
- 正确选项、错误选项和错误原因。
- 空间布局、镜头上下关系、朝向、运动方向和攻击方向。
- 点击、拖拽、选择、战斗、转场、结果等状态顺序。
- 跨镜头角色身份、装备、生命、等级、技能和资源继承。
- 禁止项，例如角色变形、技能串位、镜像翻转、真实人手、乱码、水印、随机 Logo。

不要新增用户没有提供的角色、技能、敌人属性、福利奖励或复杂流程；需要补足时标注为广告简化假设。

### 三、Playable主路径

用一段箭头流程描述主路径，按实际顺序写出开场、选择、技能查看、拖拽、战斗、换角、结果和 CTA 节点。节点数量必须与用户需求一致，不合并用户指定的关键决策。

示例格式：

```text
玩家进入画面 -> 危机出现 -> 点击查看技能 -> 选择正确角色 -> 拖入目标区域 -> 系统反馈 -> 进入战斗 -> 点击技能 -> 结果页/CTA
```

### 四、分镜脚本表

保留表格形式，不把分镜改写成纯段落。表头固定为：

| 镜头号 | 时间安排 | 镜头截图 | 镜头内容 | 玩家操作与反馈 | 屏幕文案 | 制作重点 |
|---|---|---|---|---|---|---|

截图缺失时写“【截图待补】”并补充构图说明，不伪造已有截图。每个镜头都要写清：镜头状态、画面动作、玩家输入或自动触发、成功/失败反馈、文案和验收重点。真实 Playable 的等待输入要标注建议上限，不把自动演示误写成玩家已完成。

如用户给的是 15 秒演示稿，应按时间码拆分；如用户给的是真实可玩流程，应使用“最早出现时间 + 等待上限 + 无操作处理”描述交互段。

### 五、交互逻辑说明

用编号条目说明程序可执行的状态逻辑，至少覆盖：

1. 点击、长按、拖拽、滑动或选择的对象。
2. 起点、终点、命中区域、松手条件和成功判定。
3. 错误点击、错误拖拽、空白点击、重复输入和触摸中断。
4. 无操作时状态是否停留、回弹、重试或继续提示。
5. 状态解锁顺序、选择结果和跨镜头状态继承。
6. 失败、重试、退出和 CTA；仅在用户流程存在时写入。

如果某个节点是演示视频中的自动播放段，要明确“演示自动播放；真实 Playable 可配置为等待玩家输入”。

### 六、无操作引导

按当前可操作状态出现后的时间点说明提示层级。推荐写法：

- 2 秒无操作：目标轻微浮动、按钮扩散光圈或可操作区高亮。
- 4 秒无操作：目标闪光、路径虚线或下一步区域呼吸。
- 6 秒无操作：半透明白色手指演示一次操作轨迹。

手指演示只能引导，不能自动完成最终点击、拖拽、松手或选择。玩家开始触摸后隐藏引导手势。

### 七、美术、动画与程序验收

按分类输出验收清单，至少包含：

- 角色与 UI：外观一致、卡牌不重绘、图标不串位、文案不乱码。
- 交互与反馈：点击波纹、拖拽吸附、失败回弹、正确标记、技能反馈。
- 空间与连续性：上下关系、朝向、移动方向、攻击方向、镜头切换前后状态。
- 声音与文字：静音也能理解，文案短、可读、安全区不遮挡。
- 禁止项：真实人手、水印、随机 Logo、镜像翻转、重复角色、错误技能归属。

把用户特别强调的红线放在最前面，作为最高优先级验收项。

### 八、建议埋点

使用事件清单或表格记录：曝光、首次交互、点击开始、点击成功、拖拽开始、拖拽成功、拖拽失败、选择、技能预览完成、战斗开始、战斗完成、换人、转盘完成、结果页和 CTA。

明确演示手势不计入真实玩家事件。字段名可用英文小写下划线，SDK 和字段实现由平台或开发团队确认。

### 九、模板复用说明

说明下一次项目可以替换哪些字段：项目基础、角色与技能、敌人和弱点、操作对象、时间码、文案、平台、验收版本和 CTA。标出本次项目的专属规则，避免复用时误当成通用玩法。

## 输出判断

- 用户只给线性视频需求时，可以按固定时间码写演示脚本，但要明确“线性演示”与“真实 Playable 等待输入”的区别。
- 用户要求 Playable 制作稿时，必须补齐操作起点、终点、命中、反馈、状态更新和异常路径。
- 用户要求“直接对接内容”时，少讲方法，直接输出制作方可执行稿。
- 用户要求“模板”时，使用占位符如【项目名】、【正确角色】、【技能名称】、【敌人弱点】。
- 用户要求“不直接输出表格”时，保留第四部分分镜表，其余部分使用说明和编号条目；除非用户明确要求，避免把全文做成多张表。
- 交付前逐镜回放角色身份、空间上下关系、物件数量、操作顺序和总时长，修正规则漂移、流程膨胀和自动完成问题。
